## TikFinity: behavior documented by its public FAQ

The FAQ describes an event/action model: creator events (examples include a specific gift, likes, a viewer joining) trigger configured Actions. Actions can include visible alerts and sound effects; actions can be tested with a test/play control. A screen generated by the product is then added as a browser/link source to OBS or TikTok LIVE Studio. The FAQ also recommends user cooldowns and limiting who can trigger TTS to reduce unwanted repeated speech. The FAQ explicitly says it does not offer a TTS word filter in the version described by that document.

For Minecraft, the FAQ documents a setup based on a Paper server and a ServerTap plugin, followed by a configured Minecraft command in an action and an event binding. Its instructions include local and externally hosted server connections. Those are the public setup directions from the FAQ; GiftStream intentionally keeps its own local vanilla server and restricted action catalogue rather than exposing an arbitrary console-command field.

Source: [TikFinity Public Docs FAQ](https://github.com/zerodytrash/TikFinity-Public-Docs/blob/main/faq-en.md).

## Public community Minecraft adapter: observed mechanics

The third-party `TikTokLIVEMC` repository is a Bukkit/Spigot plugin that documents a TikFinity webhook connection. Its README describes generating a URL with `/tiktoklive generate`, pasting it into a TikFinity webhook action, then mapping events/gifts to actions in plugin configuration. The inspected source/config exposes these behaviors:

- Target selection can include every online player, the first player to join, or a configured player; commands also allow adding/removing selected players.
- Action keys can match gift IDs, gift names from a local gift list, or configured TikFinity action names. The config describes matching multiple IDs/names/coin groupings.
- Configurable effects include one or multiple commands (as console or player, with an optional random command), player messages, action-bar text, sounds, teleports using absolute or relative coordinates, random health, and mob spawning with amount/name/taming and configured or randomized spawn distances.
- The documented non-legacy connection polls a remote reader at a configured tick interval. The legacy mode opens a server socket; the config labels it public-server-only and not recommended. Both modes place a password in the generated connection URL/config exchange.
- An AntiSpam section controls reconnection/event timing for the legacy socket mode.

This is a historical third-party beta adapter, not a current endorsed setup. It demonstrates a broad public configuration vocabulary, not a recommendation to expose a Minecraft console or to copy its implementation. GiftStream keeps its RCON loopback-only, validates player names, encodes chat as data, and exposes specific allowlisted actions.

Sources: [README](https://github.com/TimeCodings/TikTokLIVEMC/blob/master/README.md), [config.yml](https://github.com/TimeCodings/TikTokLIVEMC/blob/master/src/main/resources/config.yml), [TikTokSocket.java](https://github.com/TimeCodings/TikTokLIVEMC/blob/master/src/main/java/dev/timecoding/tiktokspawn/socket/TikTokSocket.java), [TikTokLiveCommand.java](https://github.com/TimeCodings/TikTokLIVEMC/blob/master/src/main/java/dev/timecoding/tiktokspawn/command/TikTokLiveCommand.java).

## Public overlay editor feature set

The third-party Overlayed README advertises multiple iframe widgets, drag/resize/rotation, opacity/zoom/position/size, z-index layer ordering, borders, canvas zoom and resolution guides, locks, presets, autosave, JSON import/export, and three share modes: preset URL, encoded static layout, and auto-save layout. Those are the project author's stated features, not independently benchmarked runtime guarantees.

GiftStream already has OBS/browser-source URLs, layouts, landscape/portrait canvas presets, drag/resize for LIVE Arena widgets, saved positions, per-widget layer ordering and rotation controls, theme/accent, scale, opacity, density, visible fields, title, and an editable preview. These controls preserve the transparent OBS canvas; the selected widget and transform are saved through the validated config API.

Source: [Overlayed README](https://github.com/BadWise/TikFinity-Overlay-Editor/blob/main/README.md).

## Creator-supplied LIVE reference (November 2026)

A user-provided TikTok LIVE screenshot shows a portrait Minecraft challenge HUD: `0/5 WINS`, a short jail countdown credited to the viewer who triggered it, a `LEVEL 94 / 100` readout, and an at-a-glance gift/event legend (`Rose = PUNCH`, another gift = JAIL, `FOLLOW = TNT`), plus a viewer streak reward. This is a creator's concrete example, not evidence of a TikTok platform standard. It reinforces the value of readable mobile-safe game state, compact gift/action tiles, verified coin-price labels, and visible attribution. GiftStream already exposes Parkour level in the map HUD and the overlay's rule rails; this update adds verified price/threshold chips plus a jail/punch callout with a sender-attributed countdown in LIVE Arena. A five-win counter and TNT action are not inferred from the screenshot because GiftStream's current Parkour/Dropper maps do not yet define those game rules.

## GiftStream status and work derived from the review

GiftStream currently has normalized gift/like/follow/comment/join/share/subscribe events; rule presets with thresholds, global cooldown, priority metadata, sounds, streak handling and TTS; local event relay; safe gift-price matching; configurable OBS overlays; and local Minecraft Parkour/Dropper modes.

### Implemented in this update

- **Per-viewer rule cooldown:** independently throttles repeats from one viewer, without suppressing other viewers when global cooldown is zero. Global and per-viewer limits can be combined, and the setting is editable in the rule form.
- **Minecraft action fidelity and stability:** Parkour/Dropper push fires a Punch II arrow toward the player from a random direction (the arrow is weakly damaging rather than an instant teleport); fixed map-supported landing positions avoid treating datapack selector `dy` as a course elevation, and jail cells are built before teleport with a return to the configured lobby spawn.

### Evidence-led next milestones

1. Add reusable named overlay layout presets and safe JSON import/export around the now-editable widget positions, layers, and rotations.
2. TTS phrase moderation and clearer per-viewer/role limits, with a local preview before enabling speech.
3. A clearly marked event replay/test bench separated from real LIVE counters and earnings.
4. Better per-event execution diagnostics (queue delay, dedup/source visibility, action result) without retaining comment contents unnecessarily.

## Public TikTok LIVE game tooling review (November 2026)

This is a review of public documentation and repository metadata—not decompilation, protocol interception, or copying another product's UI, assets, or implementation.

- **TikFinity's public product page** models interaction as a legible `WHEN → THEN` rule, with a direct test control, gifts/likes/follows/comments as triggers, and overlays, goals, wheels, sounds, and game actions as outcomes. This validates GiftStream's rule editor and local action test, and suggests that the on-stream explanation of each rule should remain immediately readable. Source: [TikFinity](https://tikfinity.com/).
- **NabeelFK/tiktok-live-minecraft-bridge** is an MIT-licensed public repository. Its README describes a normalized gift map feeding a rate-limited action queue, plus offline stdin test, JSONL record/replay, server command syntax verification, gift-catalog key/price checks, and a compact mobile overlay that visually distinguishes helping from sabotaging gifts. This is useful architectural evidence, not a benchmark or endorsement. Source: [repository](https://github.com/NabeelFK/tiktok-live-minecraft-bridge), [license](https://github.com/NabeelFK/tiktok-live-minecraft-bridge/blob/main/LICENSE).
- **SmooGames TikTok Live Connector** publicly lists likes, comments, gifts, and a companion-app command editor. Its CurseForge listing says **All Rights Reserved**; we used only its published feature description and did not inspect, redistribute, or adapt its binary, code, or artwork. Source: [CurseForge listing](https://www.curseforge.com/minecraft/mc-mods/tiktok-live-connector).

### Implemented from this review

- **Help / sabotage chips in LIVE Arena:** built-in Parkour and Dropper actions now carry an explicit Polish or English label and color treatment on the portrait-friendly action cards. Help effects use green; disruptive effects use rose. Unknown or custom actions are not guessed or misclassified. This is a GiftStream-native adaptation of the general clarity pattern, not a copied layout.

### Next evidence-led engineering steps

1. Add a local event scenario bench that replays normalized fixture events through the real rule matcher while keeping LIVE counters, earnings, and Minecraft execution completely untouched by default; require an explicit opt-in for live-game tests.
2. Serialize and rate-limit bursty Minecraft actions, expose bounded queue depth and result state, and define coalescing/priority semantics so a gift combo cannot flood RCON or block urgent cleanup/reset actions.
3. Add safe, version-aware command validation against the actual local server without executing the proposed effect, then keep confirmation/testing separate from live execution.
4. Validate action polarity in the built-in rules; the classification must be editable or omitted for custom rules rather than inferred from arbitrary rule names.
5. Expand specific game mechanics through allowlisted actions, not arbitrary remote console execution.

TikTok ingestion remains an unofficial client integration and needs ongoing compatibility checks against publicly observable behavior and current provider documentation.
